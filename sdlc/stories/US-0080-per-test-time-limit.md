# US-0080: Per test time limit

> Spec: SPEC-0014 (sdlc/specs/SPEC-0014-lifecycle-test-reliability/)
> Nature: BUG
> Priority: P1
> Depends on: main
> min_tier: 2
> Files touched: 5
> Closes spec: no

## Objective

Nothing bounds a test's duration today: a hung test turns `make check` into a process that never ends, with no
test named (BUG-003). This story gives every test a 60 second limit and every `slow` test a 900 second limit; a
test over its limit fails alone, named, with `Timeout`, and the run goes on to a non zero exit.

## Requirements covered

- SPEC-0014/BR-012: The test suite SHALL limit each test to 60 seconds, and each test marked `slow` to 900 seconds.
- SPEC-0014/BR-013: IF a test exceeds its limit THEN THE test run SHALL report that test as failed with its node id and the word `Timeout` in its failure, SHALL run the remaining tests, and `make test` and `make check` SHALL exit with a non zero status.

## Independent Test

`make test ARGS='-k suite_time_limit'` (part of `make check`): a child pytest run with the project configuration
and `-o timeout=2` on a throwaway file holding a 10 second sleeper and a passing test exits 1 in less than 8
seconds, prints the sleeper's node id with `Timeout`, and `1 passed` (red today: no plugin, the child runs 10 s
and exits 0).

## Design excerpt

### Decisions
- DEC-007 (SPEC-0014): "Per test limit by `pytest-timeout` 2.5.0, dev dependency `"pytest-timeout>=2.5.0"` added with uv and locked; `[tool.pytest.ini_options]` gains `timeout = 60` and `timeout_method = "signal"`." The signal method fails the test with `Timeout (>60.0s) from pytest-timeout.` and the run continues; the thread method would end the process. Version from context7 `/pytest-dev/pytest-timeout` (`version = 2.5.0`, requires `pytest>=8.4.0`; locked pytest is 9.1.1).
- DEC-008 (SPEC-0014): "The 900 second limit of `slow` tests is applied by a `pytest_collection_modifyitems` hook in `tests/conftest.py` that adds `pytest.mark.timeout(SLOW_TEST_TIMEOUT_SECONDS)` to each item carrying the `slow` marker (an explicit `timeout` marker on a test is left as is). Child runner tests load the hook with `-p tests.conftest`, cwd at the repository root and `-c pyproject.toml`."
- DEC-009 (SPEC-0014): the literal value check BT-016 carries `@pytest.mark.slow`; the default run carries short counterparts: "a child run with `-o timeout=2` (sleeper of 10 s reported `Timeout`, one other test passing, exit 1; a `slow` test sleeping 3 s under `-m slow -o timeout=1` passing, which proves the 900 marker outranks the ini value)".

### Contracts
```toml
# pyproject.toml
[dependency-groups]
dev = [ ..., "pytest-timeout>=2.5.0" ]      # through uv (make sync after editing), uv.lock updated

[tool.pytest.ini_options]
timeout = 60
timeout_method = "signal"
```
```python
# tests/conftest.py
SLOW_TEST_TIMEOUT_SECONDS = 900

def pytest_collection_modifyitems(config: pytest.Config, items: list[pytest.Item]) -> None:
    """Give every test marked slow its own 900 second limit (SPEC-0014/BR-012)."""
```
Child runner command used by the tests (a helper inside the test file):
`[sys.executable, "-m", "pytest", "-c", str(REPO / "pyproject.toml"), "--rootdir", str(REPO), "-p", "tests.conftest", "-p", "no:cacheprovider", *extra, str(test_file)]`
with `cwd=REPO`, `capture_output=True`, `text=True`, and a `timeout=` on `subprocess.run` larger than the expected
duration (the test must not hang either).

## Acceptance tests

> 100% must pass, run through `make check` (or the project target). Never run test files ad hoc.

Location `tests/test_suite_time_limit.py`. The throwaway test files are written under `tmp_path`.

### SPEC-0014/BT-016: A test over its limit fails, the run continues
- Level / Driver / Location: functional e2e, `slow`; test runner as child process; `tests/test_suite_time_limit.py`
- Preconditions: a file under `tmp_path` holding `test_sleeper` (`time.sleep(120)`), `test_ok` (`assert True`) and `test_slow_sleeper`, marked `@pytest.mark.slow`, sleeping 70 seconds
- Given that file and the project configuration (`-c pyproject.toml -p tests.conftest`, no `-o timeout`)
- When the runner runs `test_sleeper` and `test_ok` (default selection, `slow` deselected)
- Then it exits with status 1 in less than 90 seconds, its output names `test_sleeper` with `Timeout`, and shows `1 passed`
- When the runner runs `-m slow` on `test_slow_sleeper`
- Then it reports `1 passed`
- This test itself carries `@pytest.mark.slow` (DEC-009); it runs with `make test ARGS='-m slow -k suite_time_limit'`.

### Default run counterparts (support tests of this story, not spec ids)
- `test_short_limit_fails_the_sleeper_and_runs_the_rest`: child run with `-o timeout=2` on `test_sleeper` (`time.sleep(10)`) and `test_ok`: exit status 1, elapsed under 8 seconds, output contains `test_sleeper` and `Timeout`, and `1 passed`. Red before this story (no plugin: `-o timeout` is an unknown key warning, exit 0 after 10 s).
- `test_slow_tests_get_their_own_limit`: child run `-m slow -o timeout=1` on a `slow` test sleeping 3 seconds: `1 passed` (the marker added by the hook outranks the ini value).
- `test_the_configured_limit_is_60_seconds`: read `pyproject.toml` with `tomllib`: `timeout == 60`, `timeout_method == "signal"`; and `tests.conftest.SLOW_TEST_TIMEOUT_SECONDS == 900`.

## Constraints

- Files not to touch: `Makefile` (the Python targets stay identical to the template), product code under `src/`.
- Dependencies not to add: anything but `pytest-timeout`.
- Patterns to avoid: `timeout_method = "thread"`; running pytest ad hoc outside `make` in the story's own workflow (the child runs inside tests are the driver of BT-016, which is allowed); marking slow tests one by one.
- Scope boundary: the stdio read bound (BR-014) is US-0081.
