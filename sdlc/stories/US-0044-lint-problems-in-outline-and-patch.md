# US-0044: Lint problems in `outline` and `patch`

> Spec: SPEC-0007 (sdlc/specs/SPEC-0007-agent-editing-tools/)

## Objective

Connects lint to the two commands that report it: `outline` counts the problems of each slide (warnings included) and `patch` lists the problems of the slides it touched.

## Requirements covered

- SPEC-0007/FR-NEW-001 (partial: the `problems` count per slide): WHEN an agent or a user asks for the `outline` of a file THE Editor SHALL return a JSON object describing the file structure without any image data.
- SPEC-0007/FR-NEW-011: WHEN a patch succeeds THE Editor SHALL return `{"ok":true,"changed":<bool>,"slides":<count after>,"problems":[...]}` where `problems` holds the lint problems of the slides touched by the patch.

## Independent Test

`make test ARGS='-k deck_lint_wiring'`: `outline` of DECK-EI with a remote image in `slide-2` shows `problems` 1 for that slide and 0 for the others; a `replace_slide` of `slide-1` of DECK-MED by a slide with an image and no source returns `problems` equal to the single L009 object with `slide` `slide-1`.

## Design excerpt

### Decisions
- DEC-008 (SPEC-0007): Problem ordering and slide column fallback `slide-<index>`.
- DEC-003 (SPEC-0007): atoms carry `touched`; a replaced or inserted slide is touched, and `set_text` touches its slide.
- DEC-005 (SPEC-0007): problems are computed on the assembled and renumbered result, so slide ids are the ones after renumbering.
- Interpretation chosen: problems of a dry run are computed on the computed result like a real run; whole file problems (slide `-`) are not listed in a patch result.

### Data model
Patch result: `{"ok":true,"changed":true,"slides":8,"problems":[{"code":"L009","severity":"error","slide":"slide-1","message":"slide has an image and no source line"}]}`; outline slide entries: `problems` = number of lint problems of that slide, warnings included.

### Contracts
`outline`: `lint_deck(deck)` is computed once; the problems with `slide_index == i` are counted into `slides[i]["problems"]`. Whole file problems are not counted in any slide.
`apply_patch`: after the final assembly and renumbering, lint the assembled text (`load` from text, not from the file) and keep the problems whose slide index belongs to a touched slide: slides set (`set_text`, even when the text did not change), replaced or inserted; each problem is rendered `{"code","severity","slide","message"}` with `slide` the id after renumbering. Order: slide order, then code. Problems of other slides and whole file problems are not listed. With `dry_run` the same list is returned. A patch that is rejected returns no result (error only).
A failing lint never blocks the write: errors and warnings are information in the result (E2E-027 expects `ok` true and the file written).

### Additional tests (same file)
- Outline counts warnings and errors together: a slide with one L010 and one L006 has `problems` 2; a whole file L002 problem is counted nowhere; DECK-EI outline has `problems` 0 on all slides.
- Patch result problems restricted to touched slides: on a DECK-EI where `slide-5` already has an L006 and a `set_text` touches `slide-2`, the result `problems` is `[]`; a `set_text` that does not change the text still lints its slide and lists its problems; an `insert_slide` after `slide-4` of a slide with `Contenu de la slide` lists `L006` with `slide` `slide-5` (id after renumbering).
- Dry run returns the same `problems` as the real run and writes nothing.
- A patch that produces problems still writes the file (`changed` true).
