# US-0041: `patch` tool and editor flag

> Spec: SPEC-0007 (sdlc/specs/SPEC-0007-agent-editing-tools/)

> min_tier: 2
> Files touched: 4

## Objective

Exposes `patch` on the agent tool surface with the editor flag `update_in_progress` true only around the real write.

## Requirements covered

- SPEC-0007/FR-NEW-003 (partial: tool surface `patch(file, ops, dry_run=false)`, update flag, modification time rule): WHEN an agent or a user applies `patch` with a list of operations THE Editor SHALL validate all operations before writing, then write the file once, atomically, so that either every operation is applied or none.
- SPEC-0007/FR-NEW-016 (partial: patch only): The Editor SHALL give the same result for each of these operations through the command line and through the agent tool surface, the tool surface returning an error whose message is the command line error line without its `error: ` prefix.

## Independent Test

`make test ARGS='-k deck_patch_tool'`: with an in process editor server running on DECK-EI, `patch` through `fastmcp.Client(mcp)` with a `set_text` returns `{"ok":true,"changed":true,"slides":8,"problems":[]}`, then `get_status` shows `update_in_progress` false and an mtime later than the forced earlier one (`os.utime` to 1_000_000_000 before).

## Design excerpt

### Decisions
- DEC-011 (SPEC-0007): "The update flag is toggled through an injected callback `set_update_flag`; `mcp_server.patch` passes `get_state().set_update_flag`, the command line passes none. It is true only around the real write."
- DEC-009 (SPEC-0007): service layer; `DeckError` becomes `ToolError(<msg>)`.
- DEC-013 (SPEC-0007): "the tool parameter `ops` is `list[Any]`" so the spec's own messages report a malformed operation.
- Skill rule: `trace_span("mcp.patch")`; no stdout in the MCP process.

### Data model
Result of the tool: the dict of `apply_patch` (keys `ok`, `changed`, `slides`, `problems`, plus `dry_run` when true).

### Contracts
```python
@mcp.tool() def patch(file: str, ops: list[Any], dry_run: bool = False) -> dict[str, Any]
```
Body: `with trace_span("mcp.patch"):` call `apply_patch(file, ops, dry_run=dry_run, set_update_flag=get_state().set_update_flag)`; `DeckError` becomes `ToolError(str(exc))` (message without `error: `). The flag is true only around the real write (US-0038 contract), false afterwards even when the write fails; the modification time changes only when the file changed; a dry run or a no change patch never touches the flag or the mtime.
Line added to `## Tools` in `skill/core.md`: `- patch: Apply validated, atomic, self renumbering slide operations (set_text, replace_slide, insert_slide, delete_slide, move_slide) to a presentation; dry_run validates only.`
`.agent_docs/observability.md`: spans `mcp.patch`, `deck.*` operations, `file.write` emitted by `atomic_write` (attributes `file.path`, `file.size`).

### Additional tests (same file)
- Tool result shape: for a `set_text` the object equals `{"ok":true,"changed":true,"slides":8,"problems":[]}`; with `dry_run` true it also has `"dry_run":true` as last key and the file is unchanged.
- Error text without prefix: an unknown operation gives the message `patch failed at operation 1: unknown operation "frobnicate" (nothing written)` (no `error: `); equals the command stderr line minus the prefix.
- The flag is false after a failing patch (unknown id) and after a failing write (target directory made read only): a spy callback records `[True, False]` for the successful write and `[]` for a validation failure.
- Template refusal through the tool: `patch` on a copy under `templates/bootstrap/x.html` fails with `Refusing to modify a template: templates/bootstrap/x.html`.
- The skill audit: the `## Tools` section of `skill/core.md` has a line starting `- patch:` and `mcp-htmleditor skill-audit` exits 0.
- The tool list of the server contains `patch`; a malformed `ops` (`[3]`) reaches the spec message `patch failed at operation 1: operation must be an object (nothing written)` instead of a framework validation error.
