# AGENTS.md — mcp-htmleditor

## Overview

WYSIWYG HTML editor + MCP server. LLM agents modify HTML files on disk; the browser auto-reloads via polling.

## Key commands

```bash
pip install -e .                          # Install
mcp-htmleditor templates                  # List available templates (ei, carbon, doc)
mcp-htmleditor new ei pres.html --serve   # Create from template + open editor
mcp-htmleditor serve file.html            # Open editor on existing file
mcp-htmleditor mcp                        # MCP server (stdio)
mcp-htmleditor export pptx in.html out.pptx
mcp-htmleditor export docx in.html out.docx
```

Template keys: `ei` (Euro-Information slides), `carbon` (IBM Carbon slides), `doc` (Word-like document), `doc-perso` (Perso charter document), `doc-ei` (Euro-Information document).
Bootstraps live in `templates/bootstrap/`, full examples in `templates/reference/`.
The `new` command copies a bootstrap; template files are read-only via the server.

`templates/bootstrap/slides-ei-empty.html` is GENERATED by `make bootstrap-ei`
(`tools/gen_ei_bootstrap.py`) from `templates/reference/slides/euro-information.html`:
the reference is the single source of the EI charter CSS. Never hand edit the bootstrap;
edit the reference and regenerate, otherwise `new ei` stops producing the validated charter.

### Dev commands (Makefile)

```bash
make sync        # pip install -e .
make lint        # ruff check src/
make lint-fix    # ruff check --fix src/
make format      # ruff format src/
make typecheck   # mypy src/ (strict)
make test        # pytest tests/
make test-cov    # pytest with coverage (gate 70%)
make check       # lint + typecheck + test-cov
make bootstrap-ei # regenerate templates/bootstrap/slides-ei-empty.html from the EI reference
make clean       # remove build/test/cache artifacts
```

JS is vanilla, no build step: validate with `node --check src/mcp_htmleditor/static/*.js`.
Coverage measures the *installed* package, so run `make sync` (editable install) before
`make check`, otherwise a stale non-editable install is measured and unrelated tests fail.

Tooling note: `ruff` and `mypy` are invoked as direct binaries (global installs),
not `python3 -m ruff`. `pytest` runs via `python3 -m pytest`. `mypy` runs in its
own uv-isolated env, so third-party import stubs are handled via
`[[tool.mypy.overrides]]` (bs4, pptx, fastmcp, click) with `ignore_missing_imports`.

## Architecture

- `state.py` — singleton in-process state + `.mcp_state.json` on disk
- `http_server.py` — ThreadingHTTPServer, routes: `/`, `/static/*`, `/content`, `/status`
- `mcp_server.py` — FastMCP with 6 tools
- `cli.py` — Click CLI: `templates`, `new`, `serve`, `mcp`, `export`
- `templates.py` — template registry (key → bootstrap file): ei, carbon, doc, doc-perso, doc-ei
- `export/to_pptx.py` — HTML → PPTX: slide detection (`data-type="slide"` on any tag, `article.slide` fallback), per-charter chrome, vertical block flow, one renderer per component (text, grid, panel, table, gantt, arch diagram, annotated image, image, hbar). Returns an `ExportReport` (slide count + warnings); the CLI prints it and exits non zero when nothing was exported
- `export/pptx_style.py` — `Box` geometry in inches on the 960x540 canvas (1 CSS px = 1 pt), CSS parsing (lengths, colours, custom properties), `Theme` charters (ei / carbon / generic), `TextStyle` scale per class, `StyleResolver` (index of single-class CSS rules + inline styles)
- `export/pptx_components.py` — pure helpers: `TableGrid` (colspan/rowspan occupancy grid, column widths), Gantt period maths, CSS transform composition, table cell borders and theme-style removal (python-pptx has no API for those)
- `export/to_docx.py` — HTML → DOCX (pandoc `-f html`): preprocesses the HTML so the title is emitted once (`.doc-title`/`.doc-subtitle` lifted into pandoc metadata), applies the charter through `--reference-doc`, reports SVG and pandoc warnings
- `export/reference_docx.py` — generates a charter `reference.docx` (patches `word/styles.xml` of pandoc's own default), cached in `~/.cache/mcp-htmleditor/reference/`; charters `perso` and `ei`
- `static/editor.js` — iframe renderer, polling, rich-text toolbar, slide insert, doc-block insert (avant/apres), image embed, drag-reorder des blocs document (poignee), deplacement des arch-nodes a la souris (data-x/data-y en %)
- `static/slide-layouts.js` — per-template slide layouts (LAYOUT_SETS.carbon / .ei)
- `tools/gen_ei_bootstrap.py`: regenerates the EI slides bootstrap from the EI reference
- `tools/check_ei_insert.py`: browser check of EI slide insertion (footer logo, `.logo-disc`,
  page renumbering) plus PNG captures to review. Needs playwright, out of `make check` scope
  because it drives a real browser. Run it after touching the EI bootstrap, `slide-layouts.js`
  or `renumberSlides`/`resolveTemplateAssets`
- `static/doc-blocks.js` — document block definitions (DOC_BLOCKS: title, subtitle, heading1-5, paragraph, table, list)

## LLM workflow pattern

```
update_start() → write HTML file → update_end()
```

Never modify the file without these flanking calls.

## PPTX export: how to validate a change

Never trust the slide count alone, look at the pixels:

```bash
mcp-htmleditor export pptx pres.html /tmp/out.pptx
soffice --headless --convert-to pdf /tmp/out.pptx --outdir /tmp/
pdftoppm -jpeg -r 72 /tmp/out.pdf /tmp/slide   # then read /tmp/slide-N.jpg
```

Regression set: `templates/reference/slides/euro-information.html` (3),
`example-ei-complete.html` (9), `ibm-carbon.html` (9, no `data-type`),
`example-carbon-complete.html` (9), `presentation-standard.html` (4, legacy
`<section>`), `roadmap-one-pager.html` (1, gantt with `margin-left`).

## HTML conventions

- `data-doc-type="presentation"` on `<html>` → slide navigation active
- `data-doc-type="document"` → Word-like mode ("＋ Bloc" picker in edit mode)
- `data-doc-template="perso"` / `"ei"` on the document `<article>` selects the charter (HTML rendering and DOCX export both)
- `data-type="slide"` requires `data-id` (unique) and `data-title`
- `data-editable="text"` on editable text elements
- EI slide footer markup is `.slide-foot-logo > .logo-disc > img`: the template only sizes
  `.slide-foot-logo .logo-disc img` (16px), so a missing `.logo-disc` lets the chevrons
  render at 41x37px and spill over the blue ring
- Slide counters: eyebrow `Catégorie · Slide 0N / TT` in both charters, plus
  `.slide-footer-right` ("Slide N / TT", Carbon) or `.slide-foot-page` ("N", EI).
  `renumberSlides()` in `editor.js` rewrites exactly those three; anything else goes stale
- `<html data-asset-chevrons="data:image/png;base64,…">` in the EI bootstrap is the fallback
  source for `{{CHEVRONS}}` in inserted slides (`resolveTemplateAssets`), needed because a
  fresh file has no `.slide-foot-logo img` to copy from. Same pattern available for
  `data-asset-cover` / `-cm` / `-cic` / `-ei`
- Slide layouts may use `{{N}}` / `{{TT}}`: they are not substituted at insertion, the
  eyebrow regex in `renumberSlides()` resolves them on the pass that follows
- Document headings use semantic `<h1>`..`<h5>` (classes `doc-title`, `doc-subtitle`, `doc-h1`..`doc-h5`) so pandoc maps them to Word Heading styles
- Document figures use `<figure>` + `<figcaption>` (pandoc maps them to Word CaptionedFigure + ImageCaption)
- Tables in documents need a `<colgroup>` with `style="width:X%"` on each `<col>`: pandoc reads it for the DOCX column widths (`data-col-width` alone is ignored by pandoc)
- Document templates carry a `@media print` block (`@page` margins, no shadow, no break inside figures/rows, repeated `thead`)
- DOCX export caveat: the Word `Title` style comes from `<head><title>`, so a document with a `<h1 class="doc-title">` gets its title twice (see `skill/workflow-export.md`)
- Template resolution order: `HTMLEDITOR_TEMPLATES_DIR`, then `~/.config/mcp-htmleditor/templates/`
  (copied by `make install`), then `<repo>/templates/`. After editing anything under
  `templates/`, either run `make install` or export `HTMLEDITOR_TEMPLATES_DIR=$PWD/templates`,
  otherwise the installed stale copy wins and the change looks like it did nothing

## State file

`.mcp_state.json` is written next to the current HTML file.
It is gitignored. Do not commit it.

## Tests

`tests/` targets pure logic only (no network I/O):
- `test_state.py` — EditorState singleton, persistence, mtime.
- `test_http_helpers.py` — `_strip_editor_artifacts`, `_rebuild_full_html`.
- `test_export_pptx.py` — slide detection on both templates (EI `<article>`, Carbon
  `article.slide`, legacy `<section>`), absence of `<script>`/shell text in the output,
  base64 and relative image embedding, warnings for missing/remote images, table span
  merges and column widths, Gantt geometry, arch node shapes, annotation placement inside
  the image box, plus the geometry and style helpers. Reference templates under
  `templates/reference/slides/` are used as fixtures.
- `test_export_docx.py` — HTML preprocessing (single title), charter detection,
  `word/styles.xml` patching, cache and fallbacks, plus end-to-end pandoc exports
  guarded by `@pytest.mark.skipif` when pandoc is absent.

Tests run against the working tree: `pythonpath = ["src"]` in
`[tool.pytest.ini_options]` prevents a previously installed (non-editable) copy of
the package from shadowing `src/`.

The `_EditorHandler` network class and server-lifecycle functions in
`http_server.py` are marked `# pragma: no cover` (I/O boundary). Coverage omits
the thin CLI/tool wrappers (`cli.py`, `mcp_server.py`). Gate: 70%.
`conftest.py` resets the EditorState singleton between tests.
